# 规则文件模板（V9）

> 拷到你的库根目录，改名 `Agent_Rule.md`，把 `<尖括号>` 里的换成你的。
> 这个文件是**给 AI 看的**，不是给人看的说明书——所以每一条都必须是可执行的指令，不是描述。

## 一、工作根目录

- 所有工作产物都在 `<你的库路径>\` 下，不使用 C 盘与桌面。
- 根目录只允许存在：规则文件、执行准则、总索引、`项目\`、`SKILL\`（可选）、`索引\`、`bin\`、`Archive\`。
- 其余一律归位或进 `Archive\`，并在 `Archive\MOVE_LOG.txt` 记一行。

## 二、目录结构

- 一个项目一个目录：`项目\<名>\记录\` + `项目\<名>\实现\`
- `记录\`：给人看的文档（简介/详情/规则/需求/日志/源路径）
- `实现\`：给机器跑的实物（代码/素材/产物/数据）
- 每个项目必须有 `记录\简介.txt`；纯文档项目 `实现\` 留空目录即可

## 三、命名与编码

- 目录名用中文，不加日期前缀、不加版本号
- `.txt` / `.md` / `.mjs` / `.ps1` 一律 UTF-8
- `.bat` 一律 GBK(936) + CRLF
- 生成物顶部必须带 `<!-- GENERATED by ... 勿手改 -->`

## 四、细分规则

- 单个条目文件（`记录\` 下的 md）不超过 60 行，超了拆成两个

## 五、索引维护

- `索引\db.jsonl` 是**唯一真源**
- `总索引.md`、`项目\<名>\00-入口.md` 都是生成视图，**禁止手改**
- 新增/改名/废弃后跑 `node bin/reindex.mjs`

## 六、日志格式

- 位置：`项目\<名>\记录\日志.md`
- 格式：`【YYYY-MM-DD HH:MM】结论一句话`，逐行追加
- 只写结果与偏差，不写过程

## 七、检索顺序（最重要）

1. `node bin/find.mjs <关键词>` ← 第一步永远是这条
2. 命中 → 读 `项目\<名>\00-入口.md`
3. 没命中 → 换同义词重试，最多 3 次
4. 3 次都没有 → 报告「试过 X / Y / Z，均无命中」，**不许直接说「没有」**

禁止：直接读 `总索引.md` 或遍历目录来找东西。

## 八、对话规则

- 回复用中文；技术标识、命令、报错保持原文
- 不重复声明边界、不写免责声明

## 九、项目执行规则

- 改任何东西之前先 `find` 出它的 `why` / `origin`
- `why` 为空时先补，补不上就问用户，不许按名字猜
- 改结论时把旧值记进日志

## 十、存储确认规则

- 在 `项目\` / `SKILL\` 下**新建或删除**文件前，先列表说明「改哪里、改什么」
- 修改已有文件不在此列（但改前必须读完整个文件）

## 十一、快捷命令

| 想干什么 | 命令 |
|---|---|
| 找东西 | `node bin/find.mjs <词>` |
| 看全部 | `node bin/find.mjs list` |
| 展开一条 | `node bin/find.mjs show <ID>` |
| 重建索引 | `node bin/reindex.mjs` |

## 十二、禁止项

1. 禁止手工编辑 `总索引.md` / `00-入口.md`
2. 禁止同一个事实在两处写正文（第二个位置只写指针）
3. 禁止物理删除项目目录（改 `status` 字段）
4. 禁止在 `记录\` 里放代码，在 `实现\` 里放设计文档
5. 禁止新增文件后不跑 `reindex`

## 十三、失败模式

| 症状 | 先查 |
|---|---|
| `find` 0 命中 | `kw` 写全了吗；`reindex` 跑过吗 |
| 索引落后磁盘 | `find` 会自动补，持续落后就手动 reindex |
| 服务挂了 | 刚搬过目录？建 junction 回去 |
| 两个地方内容一样 | 出现了第二个正本，改成一个指针 |

## 十四、执行质量

（独立成文见 `执行准则.md`）

## 十五、自检清单（每次新增大改后过一遍）

- [ ] 每个项目 记录/实现/入口 三件齐
- [ ] `reindex` 报的 `待补 why` 比例 ≤ 30%
- [ ] 没有两个地方写着同一段正文
- [ ] 新增的东西 `find` 得到
